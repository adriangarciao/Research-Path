# Release decisions (first public release)

Status labels: **PROPOSED** (recommended, awaiting owner approval), **DECIDED**, **OPEN**. Evidence: the
[baseline audit](BASELINE_AUDIT.md). Nothing has been provisioned or deployed.

| # | Question | Status | Proposed decision | Evidence / still needed |
|---|---|---|---|---|
| R1 | Repository shape | DECIDED (observed) | Monorepo: `backend/` (Maven wrapper, Spring Boot 4.1.1, Java 21) and `frontend/` (Vite 8, React 19, npm with `package-lock.json`). No Dockerfile, `vercel.json` or Railway config exists yet. | Audit §1 |
| R2 | API topology |  **DECIDED (owner, 2026-10-20)**  | **Browser → Railway API directly over HTTPS, strict CORS** (exact Vercel production origin only). Not a Vercel rewrite proxy: a proxy hides the client IP behind Vercel's egress addresses (all users would share rate-limit buckets) and adds a second timeout. The frontend already supports a public `VITE_API_BASE_URL`. | Audit §3; CORS does not exist yet (needs implementing) |
| R3 | Client identity for rate limits |  **DECIDED (owner, 2026-10-20)**  | A configurable trusted header, **off by default**; in production `X-Real-IP` set by Railway's edge. Accept only a single, syntactically valid IP; otherwise fall back to the connection address. Never read `X-Forwarded-For`/`Forwarded`. Do **not** enable `server.forward-headers-strategy` for identity. | Railway documents `X-Real-IP` as the client IP but **does not state that a client-supplied value is overwritten** → a live spoof test on the Railway domain is a GO/NO-GO gate (audit §4) |
| R4 | H2 instances |  **DECIDED (owner, 2026-10-20)**  | Exactly **one** Railway replica; no autoscaling. Make the global daily creation cap **durable** (counted from the database) so restarts/redeploys cannot reset it; keep per-connection buckets and in-flight idempotency in memory and document that a restart resets them. The existing DB unique constraint on `idempotency_key` already prevents duplicate paths across processes. | Railway scales horizontally only by manually adding replicas; deploy overlap is not documented → observe during first deploy |
| R5 | Request time budget (M7) |  **FINALIZED (owner, 2026-10-20) for the current implementation; hosted validation pending (runbook gate G4)**  | Measured on 8 fresh topics: raw provider page 0.51–1.20 s (p50 0.69 s, n=16); whole snapshot 3.6–4.8 s at 100 candidates, 7.4–10.2 s at 200. Implemented: overall provider budget **30 s** per generation, read timeout **10 s** (≈ 8× the slowest page; also bounds the body), connect 5 s; an attempt or retry wait starts only if it fits, retries only while the budget allows, `Retry-After` honoured only within it; frontend aborts at 45 s with a retryable message; deadline failures are 503 with `Retry-After: 10`; a retry of the same search keeps its idempotency key. Keep synchronous generation (D14). Server-side cancellation when the browser gives up is **deferred** (owner): documented, and idempotency prevents a duplicate completed operation. Before launch: uncached 200-candidate paths on Railway with its managed PostgreSQL (complete request time) and concurrent same-key requests (no duplicate provider search) — `scripts/hosted-check.ps1`. If hosted numbers make the limits inadequate, report them before changing anything. | Before: worst case ≈ 165 s per page (≈ 330 s at 200). After: provider phase ≤ 30 s by construction (PROGRESS R-M7) |
| R6 | M3 (gate recall) blocker? |  **DECIDED (owner): informational hint only, no gate change — implemented (PROGRESS R-M3)**  | No gate change before release. 9 of 10 frozen topics keep 167–200 eligible candidates; only "causal inference in economics" (62) is low. Show users the eligible-pool size (already shown) and add a hint when a pool is small. Revisit with a labelled set for "method in domain" topics (D17). | Audit §6 |
| R7 | M4 (generic titles) blocker? |  **CONDITIONALLY APPROVED (owner)**: evaluate under P12; stop and present alternatives on regressions  | Same-titled works are distinct (different DOI, authors, year, publisher) — never merge them. But "quantum error correction" paths show 3 of 5 / 4 of 10 papers titled exactly "Quantum Error Correction". Add a selection constraint: at most one work per normalized title in a path, judged under P12 (coverage loss ≤ 0.02 on audit topics, D12/D16 criteria unchanged, then validation topics), plus publisher/type/year shown on cards. | Audit §7 |
| R8 | Vercel plan | OPEN (owner) | Hobby only if the use is personal/non-commercial; otherwise Pro. | Owner's intended use |
| R9 | Railway plan, region, backups | OPEN (owner) | Small instance, one region; daily volume backups **and** a tested restore before public traffic. | Owner approval of spend |
| R10 | Public launch | OPEN (owner) | **No** until every GO item has evidence. | — |
