Implemented (observed):
- Input/API: predictable problems for malformed JSON (400), wrong media type (415), wrong method (405), unknown route
  (404), oversized or invalid topic and options (400), bodies over 8 KB incl. chunked (413), database outage (503),
  anything unexpected (500 with incident id). Bodies never contain exception names, packages, SQL, driver text or
  secrets.
- Rate limits per connection: new paths 3 burst / 10 per hour, rebuilds 10 / 120 per hour, global 500 new paths per
  UTC day (bounds provider spend); 429 + `Retry-After`; bounded client table (fails closed). Plus the M11 bounds
  (4 concurrent generations, 50 revisions per path).
- Security headers on every response; no CORS; actuator limited to health/info outside the local profile.
- Provider: redirects no longer followed (the key cannot leave the configured host); existing bounded retries,
  timeouts, size and shape checks unchanged.
- Dependencies: Tomcat 11.0.24 → 11.0.27 and Jackson 3.1.5 → 3.1.8 (critical/high advisories); 0 known after.
- Performance: items batched (13 statements per regeneration regardless of size), repeats answered without
  generation; measured latencies below.
- CI: backend (Testcontainers), frontend build/lint/tests/audit, secret guards; pinned actions (SHA) and runner image;
  read-only token; no secrets. The first run caught a real portability bug (platform line separator in a pinned hash),
  fixed and verified on Windows and Linux.
