Implemented (observed):
- Product API: `POST /api/paths` (topic, experience, budget, focus; optional `Idempotency-Key`),
  `GET /api/paths/{id}`, `GET /api/paths/{id}/revisions/{n}`, `POST /api/paths/{id}/revisions` (missing options
  keep the parent's; optional `parentRevision`). One response shape for generation and regeneration: the stored
  document plus the revision list. `Cache-Control: no-store`.
- Stored per revision: snapshot, options, engine versions (optimizer, config, concept policy, sequence, document),
  request fingerprint, complete result (stages, papers, explanations, coverage with its denominator, warnings,
  disclosures, access notice), timestamps, and relational items linked to canonical publications.
- New path: one snapshot retrieval (the only provider step). Regeneration: original frozen snapshot only, no
  provider calls and no cache reads; separate child revision stored only on success.
- Atomic persistence (one transaction); DB triggers reject any UPDATE of paths, revisions or items; retrieval
  returns the stored document, never a recomputation.
- Identical inputs reuse the stored revision (fingerprint, unique constraint, row lock). Idempotency key: a
  repeated create returns the first path (200), even when it arrives while the first is still running (waits,
  no second retrieval); a reused key with a different request gets 409.
- Bounds: 4 concurrent generations (503 + Retry-After beyond), 50 revisions per path (409), budgets 5/10/15/20.
  Opaque ids: 128 random bits, base64url; malformed and unknown ids get the same 404.

Regression checks: all algorithm, provider-contract and benchmark suites green; pinned optimizer and reading-path
fingerprints unchanged; clean migrations V1–V6 on Testcontainers and on the dev DB.
Security checks: opaque ids validated before any query; no administrative or delete endpoints; compute and
revision fan-out bounded; topic length and option values validated; plain-text output; links validated upstream.

Decisions: **D15** regeneration always uses the original snapshot; refreshing sources would be a separate, visible
action creating a new path (not built). **S02 (retention, PROVISIONAL):** while local-only, anonymous paths are
kept indefinitely. Before any deployment a retention window (proposed: delete paths not viewed for 90 days, with
their snapshot if unreferenced) must be implemented and stated in the UI. Links are unguessable but not access
control, and every response says so. Concurrency de-duplication of idempotency keys is per process (DB unique key
backs it across processes).
Known limitations: synchronous generation (~5–6 s cold; D14 measured in M13); no rate limiting yet (M13); a create
without an idempotency key is not de-duplicated (the UI must send one).
