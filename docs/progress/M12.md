Milestone: M12 — Full usable React product journey
Status: PASS (2026-10-18) — create, inspect and regenerate verified in a real browser (headless Chromium, desktop
and mobile) against the actual backend and OpenAlex.
Changed: `frontend/src` (API client and types, `SearchForm`, `OptionFields`, `PathView`, `PaperCard`,
`CoveragePanel`, `RegeneratePanel`, `App` with URL state), self-hosted fonts, Vitest + Testing Library,
Playwright config and `e2e/` flow test, `scripts/e2e.ps1`, `verify.ps1` runs frontend tests.

Implemented (observed):
- Search: topic (≤ 300 characters, blank rejected, whitespace collapsed), experience, papers 5/10/15/20, focus;
  defaults Intermediate/10/Balanced. Server validation still applies and its messages are shown.
- Pending: a generic, truthful indicator ("usually takes 5–15 seconds"), no fake progress; "Stop waiting" aborts.
  Duplicate submissions are blocked; each create sends a fresh `Idempotency-Key`.
- Result: topic, settings, "N papers selected from M eligible papers examined" with retrieval date, warnings,
  stages with purposes, numbered paper cards (title linked to the source, authors with "and N more", year, type,
  citations, link kind distinguishing open access, "why it's here", in-path citation links, tags, caveat flags),
  labelled subtopic coverage with the denominator, disclosures and the link-is-not-private notice.
- Regeneration: same three controls prefilled; disabled until a setting changes; current path stays visible (dimmed)
  while rebuilding; failure keeps it and offers retry; success shows the new revision. Revision list switches
  between stored revisions. Path id and revision are in the URL, so a path can be reopened.
- The UI never recomputes ranking, order or coverage; it renders the stored document.
- No offline/demo fixture mode was added (not needed).

Tests actually run:
- Vitest (22): form defaults, blank topic, keyboard-only submit with chosen settings, length limit, disabled while
  pending; paper card with real API data, unsafe `javascript:` link not rendered, HTML-like provider text rendered as
  text, missing metadata stated, long titles/author lists; create flow (single request while pending, request body
  and Idempotency-Key, server order preserved, URL updated); regeneration keeps the old path during pending and after
  a 503, retry shows revision 2; request body carries the parent revision; 422 message shown with form kept; 500
  internals not shown; unreachable server; stop waiting; open by link; unknown path; malformed id never fetched;
  `safeHref`, notices, author lines. Fixtures are responses captured from the real backend.
- Playwright `e2e/path-journey.spec.ts`, live, desktop and Pixel 7 viewports: 2 passed (create "graph neural
  networks" with 5 papers by keyboard, stages and caveats visible, all links http(s) with `noopener`, regenerate to
  Advanced/10 → revision 2 with the revision list, reopening the revision 1 URL shows the original 5 papers,
  unknown link explained). Screenshots reviewed; on mobile the papers now come before the controls.
- `scripts/verify.ps1` → PASS (261 backend tests; frontend build/typecheck, tests, lint; secret scan) at 81132d8.

Regression checks: backend, migrations, provider-contract and benchmark suites unchanged and green.
Security checks: no `VITE_OPENALEX*`; provider text only through React text nodes (no `dangerouslySetInnerHTML`);
links only `http(s)` (client re-check on top of server validation), `target=_blank` with
`rel="noopener noreferrer"`; only 4xx and provider/busy problem details are shown, never other 5xx details; path ids
validated before requests; fonts self-hosted (no third-party requests).
Known limitations: accessibility checked by role-based tests, keyboard use and visible focus styles, not by an
automated contrast/axe audit or screen-reader session; long generation (cold ~5–15 s) has no background job (D14,
M13); the e2e test needs the live backend and is not in `verify.ps1`.
